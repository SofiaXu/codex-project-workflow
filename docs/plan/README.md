# 后续需求与计划

本目录维护尚未交付的需求，以及实施前需要明确的决定和依赖。当前内容与使用方式见[正式文档](../README.md)。

## 当前计划

当前没有待实施的计划包。产生实际独立需求时再建立相应目录。

## 组织与清理

- 一次实际独立规划使用一个 `YYYY-MM-DD-主题/` 目录，以 README.md 说明目标、状态、需求、依赖和可观察的验收条件；简单修改不强制建包。
- 同次规划按业务能力组织，保留有用的需求标识；每项正文维护一处，不按角色、测试轮次或会话拆包。
- 交付后先更新正式文档，再依据实际验收结清需求；整包完成后更新本索引并删除计划目录，不另建完成或历史目录。
- 删除前确认必要内容已经保存，原记录在 Git 中可追溯；未保存内容或必须保留的记录继续保留。外部责任说明归属，阻塞交付的依赖继续维护。
- 日志、截图、临时样例和原始验证结果进入不入库的 `artifacts/`。本目录不保存会话流水、任务元数据或重复结果表。
