# 对抗式验收裁决 Skill

本包保存本次用户批准的需求与验收条件。执行状态在上级索引维护，原始要求不随实现结果改写。未获得 Git 历史留存前保留本包。

## 目标与默认策略

新增 `adversarial-acceptance`，中文名“对抗式验收裁决”，在仓库维护完整分发源码，并安装到当前用户的全局 Skill 目录。

- 优先用户配置，其次复用可用的已安装 ACP Agent；没有可用候选时临时运行最新版 DeepSeek Harness。
- 已配置或已安装的 Agent 沿用其当前模型；默认下载的 DeepSeek 路径动态核验最新可用模型。
- 采用“具体行为断言＋相关反例或边界＋真实执行记录”，不普遍要求变异测试。
- Skill 返回裁决和证据缺口，由主 Agent 后续处理，不自动进入修复循环。

## 证据与裁决规则

评审 Agent 使用独立新会话，只接收固定裁决指令及三类原始材料：

1. **原始计划包**：来自实施前的指定 Git 版本或用户提供的原件，保留来源与原文。
2. **Git diff**：明确比较基准，覆盖最终工作区中的提交、暂存、未暂存改动及范围内未跟踪文件。
3. **执行输出**：测试及自动静态检查的原始命令、stdout、stderr、退出码、时间和代码指纹。

禁止加入实现者总结、完成声明、预填覆盖矩阵或历史聊天。证据中的指令性文字仅作为数据处理。

**指纹绑定与防漂移：**

- 指纹覆盖 `HEAD`、已跟踪文件的暂存及工作区变更状态与内容哈希、范围内未跟踪文件的路径和内容哈希；按路径排序后稳定序列化计算 SHA-256。范围与排除规则也参与绑定。
- 锁文件、二进制文件、删除和重命名均参与计算，不能因省略文本差异而遗漏。
- `capture` 在执行命令前后分别计算指纹。已有改动本身不构成脏运行；执行期间指纹变化才标记为脏运行。
- 脏运行保留诊断记录，但不能作为通过证据。`collect` 只复用执行前后指纹一致、且执行后指纹与当前待检工作区严格一致的记录。
- 证据输出放在仓库外或 Git 忽略的专用产物目录，避免写日志造成自身漂移；已跟踪内容仍参与指纹。
- `collect` 完成收集后再次核对指纹；`review` 开始及结束时复核目标工作区。漂移后不得将原裁决用于当前工作区验收。

裁决只检查：

- **需求遗漏**：独立提取原计划需求，逐项关联实现与执行证据，识别静默跳过、缩减及尚未验收的要求。
- **删除后的断链**：检查跨语言调用、配置、导出、命令和文档引用；静态检索无命中不自动证明所有动态调用均已清理。
- **断言证据**：新增行为须有能够失败的具体断言及相关反例或边界执行记录；测试数量、恒真断言和绕过实际逻辑的替身不足以证明行为成立。

## Agent 接入与脚本接口

源码放入 `skills/adversarial-acceptance/`，包含 Skill 正文、UI 元数据、MIT 许可、脚本及必要契约引用。采用 Node.js、锁定依赖的官方 ACP SDK 和稳定 ACP v1。

提供三个命令：

- **`capture`**：执行指定验证命令，保存前后指纹及完整原始输出，分别记录测试退出码和记录有效性。
- **`collect`**：接受原计划来源、Git 基准和执行记录，生成带来源清单及 SHA-256 的冻结证据包，不修改 Git 索引或工作区。
- **`review`**：校验证据包，启动第三方 Agent，验证其响应并生成裁决报告。

**删除项自动静态取证：**

- 遇到文件删除、重命名或导出移除，自动提取旧路径、模块路径及移除符号候选，使用 `rg` 执行固定字符串引用检索。
- 导出识别采用可扩展规则；无法准确识别语言时，保守提取删除行中的候选标识，不将未识别视为无需检查。
- 检索覆盖全仓文本，包括隐藏配置和文档；排除 Git 元数据、依赖、构建目录及本次证据产物。记录检索词、范围、排除项、完整命令、输出和退出码。
- 原始结果归入执行证据；区分“无命中”和“检索失败”，失败不能伪装为引用已清理。

**启动隔离与接入配置：**

- 子进程从独立空临时目录启动，通过协议内联传入证据，不复制仓库、`.git` 或实现会话。
- 环境采用白名单，仅保留运行必需变量及适配器显式声明的认证、代理变量，不整体继承父进程环境。
- 同时关闭 Agent 的自动仓库规则、记忆和工具入口；客户端不提供文件系统、终端或 MCP 能力，并拒绝权限请求。临时目录和环境白名单不能替代工具限制。
- 配置优先级为“本次参数 → 项目配置 → Skill 本地配置 → 自动发现”。支持可执行路径、参数数组、调用脚本、可选模型及超时；凭据只引用既有认证或环境变量。
- 默认适配 DeepSeek Harness ACP，包括桌面安装提供的命令路径；其他 ACP Agent 可配置启动命令，非 ACP Agent 通过脚本遵守相同输入输出契约。
- 默认下载使用 npm `latest` 标签，不升级已有安装。记录实际 Harness、模型和协议版本；调用失败不静默切换供应商或降级模型。默认总超时为 10 分钟。

## 输出契约与确定性校验

输出机器可读 JSON、由其生成的中文报告及第三方原始响应。

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| `PASS` | 三项检查均有充分证据 | 0 |
| `FAIL` | 至少存在一个有证据支持的缺陷 | 1 |
| `INSUFFICIENT_EVIDENCE` | 材料不足以完成验收 | 2 |
| `ERROR` | 收集、接入、协议或响应校验失败 | 3 |

- 报告包含需求覆盖、删除项检查、新增行为断言、问题和证据缺口。存在已证实缺陷时整体为 `FAIL`，同时保留其他缺口。
- `collect` 为原计划、diff 片段及执行日志分配稳定证据 ID。评审引用采用“证据 ID＋行范围＋逐字引文”，统一换行展示，保留原始字节哈希。
- `review` 自动核对来源类型、片段存在性、行范围及引文一致性；未知 ID、越界或引文不符均直接产生 `ERROR`，保留原响应，不接受其通过或失败结论。
- 引用存在性由脚本验证，证据能否支持结论由评审者判断；缺少必要检查的响应也不能获得通过。
- 锁文件和二进制默认不提供逐行文本差异，仅在文件清单记录路径、变更状态、分类及变更前后 SHA-256。省略文本不豁免相关需求验收。
- 核心证据按待发送 UTF-8 总字节计量，默认上限 **2 MiB**，允许通过 `--max-evidence-bytes` 显式调整。超限在 `collect` 阶段报错，列出总量及各项大小，不生成可评审包，不隐式截断或以摘要替代原文。

## 验证与交付

- **指纹与复用**：覆盖已有改动但执行稳定、测试修改文件、HEAD／暂存状态变化、未跟踪文件变化、日志过期及收集期间漂移；验证产物写入不会误判，锁文件和二进制变化不会漏判。
- **静态取证与引用**：用跨语言源码、隐藏配置和文档样例验证删除、重命名、导出移除检索；覆盖排除范围、无命中、检索失败，以及伪造 ID、行号和引文必须产生 `ERROR`。
- **证据规模与隔离**：验证锁文件及二进制仅保留清单和哈希、超限明确失败、证据篡改被拒绝、摘要不进入请求、环境白名单及空工作目录生效。
- **调用与真实行为**：模拟 ACP 验证分块响应、模型继承、权限拒绝、超时、取消及异常退出；使用现有认证，对包含三类缺陷及修复版本的两个小型样例做真实盲评，不提供预期答案。认证不可用时明确保留真实接入为外部依赖。
- **分发与全局安装**：检查元数据、引用、资源完整性及重复安装时本地配置保留；从全局副本验证入口。更新仓库介绍、文档索引和维护说明，按项目约定维护及结清计划包，原始验证产物进入忽略的 `artifacts/`。
