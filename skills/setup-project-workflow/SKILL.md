# 项目工作流初始化与迁移

把项目开发约定、正式文档、待交付计划与验证产物组织成可独立维护的结构。支持新项目初始化和已有项目迁移；产出的仓库不依赖本 Skill 或某个示例仓库的本机路径。

## 范围与适配

- 以用户指定的目标目录为准，未指定时使用当前项目。先确认目录、适用的 AGENTS.md 和已有修改；只讨论或只要求草案时不写文件。
- 本 Skill 修改目标项目的开发约定、文档组织和必要忽略项。创建业务代码、安装依赖、建立 CI、初始化 Git、修改个人全局配置属于其他任务，不因套用工作流而附带执行。
- 保留目标项目已有的有效约束和用户修改。用户本次明确选择优先；确有无法自行解决的规则冲突时，集中澄清关键决定，继续不依赖答案的工作。
- 使用项目现有语言、目录和术语。个人偏好留在全局约定；团队必需的规则应随项目保存，不依赖某位用户的全局文件。

## 执行

### 1. 读取目标事实

先查看 README、AGENTS.md、文档入口、计划和 Git 状态；按需要读取构建配置、现有脚本与 CI。记录足以完成适配的信息即可，不扫描整个业务实现。

确定项目用途与责任边界、文档主目录、按行为和依赖选择验证的方式、验证入口、产物目录、主分支及交付约定，同时核对纯说明文档的实际发布处理方式。命令、并发预算和部署分流以现有配置与项目发布约定为依据；查不到时如实说明尚未配置或尚未确认，不生成猜测命令。

分支名和 CI 触发条件只说明技术现状，不自动构成合并、推送或部署授权。沿用目标项目和本次任务已明确的交付范围；没有长期交付约定时，写为按任务授权执行，不强加自动发布，也不要求为普通初始化额外确认一次。

### 2. 选择模式

| 模式 | 做法 |
| --- | --- |
| 初始化 | 目标缺少可用约定与文档入口时，建立最小结构；已有少量文件仍按迁移方式保留和补充。 |
| 迁移 | 已有规则或文档时，优先原位整合，补齐索引和生命周期约定；仅为消除实际混乱或满足明确要求而移动文件。 |

阅读[文档组织约定](references/document-organization.md)，将逻辑职责映射到目标项目的实际位置。默认新项目使用 `docs/`、`docs/plan/`、`artifacts/`、`scripts/`；已有等价位置可以继续使用。

### 3. 写入最小结构

初始化通常只需项目 AGENTS.md、README、正式文档索引、计划索引和必要的忽略规则。README 写项目实际用途、当前状态及已知启动/验证入口；空项目可以说明实现与命令尚未建立，不虚构技术栈、成果或待办。

按需采用以下模板，已有文件只整合需要的条款，不用模板整体覆盖：

- [项目 AGENTS.md 模板](assets/project-agents.md.template)：保留简短约束和文档路由。
- [文档索引模板](assets/document-index.md.template)：只链接实际存在的内容。
- [计划索引模板](assets/plan-index.md.template)：保存未交付事项入口和组织规则。

模板中的 `{{...}}` 必须按目标事实替换；不适用的可选条款直接省略。所有链接按产出文件的位置计算。没有真实内容时不创建模块目录、日期计划包、空脚本目录或占位文件。

在项目模板现有 `{{verification_rule}}` 和 `{{delivery_rule}}` 中整合验证范围及交付例外，不追加第二套通用规则。自动部署项目的流水线尚不支持文档免部署时，保留现状并报告待改进项，不写成已生效行为；人工发布按已有约定和任务授权处理，无部署目标时按文档交付范围验收。套用工作流本身不附带改造 CI。

迁移时保留正式契约、历史决定、需求标识、未完成事项及原有保留规则。不要因为标题包含“旧”“已完成”就删除内容；只有已核对交付证据、必要内容已进入正式文档且历史可追溯时，才按约定结清对应计划。未提交或未受 Git 管理的内容不能仅以“历史通过 Git 查阅”为由删除。

若移动文件，更新入链和出链，并处理站点配置或外部公开路径对该位置的依赖。优先保持稳定路径；同一需求正文只保留一个维护位置，其余入口使用链接。

为验证产物补充范围明确的忽略规则，保留已有忽略项。`artifacts/` 等名称不能单独证明内容可丢弃；对已跟踪文件或真实业务资产，先识别用途，本次未涵盖的清理保持原状并说明。

### 4. 核对与交付

- 检查索引与链接，确保没有残留模板变量、虚构命令、空白目录骨架或示例项目专属配置。
- 核对验证规则覆盖受影响行为及依赖，交付例外符合实际发布方式与既有授权；跨模块计划的可观察阶段仍属于同一计划包，不引入逐阶段审批或重复验证。
- 对比原始内容和 Git 差异：有效规则、正式契约及未完成事项得到保留，未带入无关修改；移动文件时检查相关引用。
- 若使用 Git，执行适用的差异格式检查，并确认验证产物忽略规则实际生效；未使用 Git 时明确留存限制，不额外初始化仓库。
- 纯文档组织调整使用文档、引用和差异检查；只在实际改变构建、站点或脚本行为时补相应验证，不默认运行业务测试套件。
- 重复应用时只修复实际差额；已有内容满足约定就保持不变，不重复追加段落、创建第二套索引或更换术语。
- 按已明确授权完成必要 Git 交付。简要报告采用的模式、主要文件、保留的项目约定、验证结果及未决事项；原始验证记录留在产物目录。
