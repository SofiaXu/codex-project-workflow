# 文档组织约定

## 各类内容的职责

下面的位置是新项目默认值。已有项目可使用等价位置，索引应说明实际入口，不为名称统一强行搬迁。

| 内容 | 默认位置 | 维护边界 |
| --- | --- | --- |
| 项目说明 | 根 README.md | 用途、责任、当前状态、启动和常用验证入口；较长操作步骤链接正式文档。 |
| 开发约定 | 根 AGENTS.md | 非显而易见的项目约束、按任务读取的文档入口、验收及交付范围。 |
| 正式文档索引 | docs/README.md | 当前能力及其文档入口；不把计划中的功能描述为已实现。 |
| 后续需求与计划 | docs/plan/README.md | 尚未交付的需求、外部依赖和实施前待决定事项。 |
| 一次独立计划 | docs/plan/YYYY-MM-DD-主题/ | 同次规划的适用需求、依赖和验收条件；日期按用户时区确定。 |
| 验证产物 | artifacts/ | 日志、TRX、截图、测量、临时验证脚本等，不入库。 |
| 可复用工具 | scripts/ | 确有重复用途、可维护的工具；临时试验脚本属于产物。 |

正式文档按真实内容选择架构、模块、接入、运维、开发规范等分类，小项目也可只用少量 Markdown 文件。不要一次性生成全部分类、空表格、作者槽位或目录清单。

## 项目 AGENTS.md

保持简短，引用项目已有文档和工具。需要团队共同遵守的非显而易见约束留在仓库；不用大段复制个人全局偏好，也不要求其他贡献者安装本 Skill 才能开发。

按受影响范围路由文档，例如修改某模块时读取其契约、准备部署时读取部署说明。不要把所有文档设为每次编辑的必读材料。

验证范围按受影响的行为和依赖路径确定，不局限于修改文件所在模块。复用目标项目的验证入口；跨模块或共享能力变更在现有计划或进度说明中简述影响及验证依据，按需检查权限、事务、版本和历史数据等不变量。只因新增影响、失败修复或未解决风险补充验证，不要求独立测试方案、重复结果表或业务全量套件。将这些选择整合进模板的 `verification_rule`，不复制示例项目的命令、进程数或技术栈。

Git 交付条款必须与目标项目的授权和运行方式一致：

- 已明确默认完整交付的项目，写清实现、必要验证、文档更新、资源清理、提交/合并/推送以及实际存在的部署检查。
- 采用 PR 或人工发布的项目保留该流程，不因迁移工作流而改成直接推主分支。
- 没有长期授权或部署能力时，按任务授权执行，不虚构自动部署。仅有一个分支或 CI 文件不足以推导授权。
- 在 `delivery_rule` 中区分发布方式：自动部署项目按实际流水线判断纯说明文档是否免部署；人工发布按已有约定和任务授权处理；无部署目标时按文档交付范围验收。区分“无需部署”和“已部署”。自动分流尚不支持时保留现状并报告改进建议，不因套用 Skill 修改 CI，也不将某项目的主分支、版本判定或发布命令写成通用约定。
- 本任务的临时测试资源在不再需要时释放；任务分支和工作树在成果已合并且没有未保存工作后清理。保留用户原有修改、持久数据和其他任务资源。

## 计划生命周期

形成实际计划时才建立日期目录。一个目录承载一次独立规划，不按角色、接口数量、测试轮次或聊天次数拆包。简单任务不必为了使用本工作流额外产生计划。

每个计划以 README.md 为入口，说明目标、当前状态、需求文件及依赖。需求少时直接写在入口；内容多时按业务能力拆分，每项需求保留一个正文和有用的原标识。

需求应包含：目标与使用者、现状和待交付差额、适用范围、依赖或待确认输入、可观察的验收条件及真实状态。按实际需要区分未实施、待业务确认、待真实接入和待正式验收，不制作重复状态表。

跨模块计划优先安排能提前验证关键假设的可观察阶段，仍保留在同一计划包并保持整包交付目标。阶段不增加审批；必须原子交付的变更保持整体，已有有效验证不重复执行。

外部责任可以从本项目待办中结清并说明归属，但不能宣称对方已经实现或验收。仍阻塞本项目交付的外部依赖继续保留。

交付后将最终行为、接口、权限、错误、配置和必要操作写入正式文档，可重复验证进入正式测试或通用工具。核对证据后删除已交付条目；整包完成后更新索引并删除计划目录，不额外建立完成/历史计划目录。此规则依赖必要内容已正式保存且原记录在 Git 中可追溯；未受版本管理、存在未保存内容或已有必须遵守的保留要求时先保留，并说明差额。

## 事实、证据与重复应用

接口存在、测试替身通过、部署健康、现场验收和生产容量分别证明不同事实。正式文档与计划状态只表述已有证据支持的范围；迁移文档本身不完成业务需求。

正式文档不保存聊天流水、任务 JSON、工作树清单、首败日志或原始验收记录。数据包来源、业务审计、法规留存和可复现输入可能属于正式契约，不能按“验证产物”自动移走或忽略。

迁移前识别内容归属和已有修改；迁移后核对规则、需求及链接。重复应用应整合到同一位置：不重复追加相同条款，不建立平行的 docs/documentation 或 plan/plans 树，不因再次执行就改变完成状态。

模板只提供表达起点。生成文件应使用真实路径和事实；移除不适用条款，替换全部模板变量。新项目没有命令、模块或计划时如实说明当前状态即可。
