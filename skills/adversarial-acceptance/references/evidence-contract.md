# 证据与裁决契约

## 输入与指纹

入口为 [adjudicate.mjs](../scripts/adjudicate.mjs)，`--help` 给出完整参数。三个命令均显式接收 `--repo` 和新的 `--out` 目录；路径含空格时按所用 shell 正确引用。测试命令使用原生可执行文件与参数数组，脚本带显式解释器。

`capture -- <executable> <args...>` 保存 `run.json`、`stdout.raw`、`stderr.raw`。测试退出码和记录有效性分开保存：测试失败不等于捕获失败，测试通过也不能使脏运行有效。退出码为干净成功 0、测试失败 1、脏运行 2、启动或捕获错误 3。

工作区指纹包括 HEAD、索引条目、全部已跟踪文件的路径/类型/执行位/原始内容哈希，以及范围内非忽略未跟踪文件的路径/类型/内容哈希。删除、符号链接本身、锁文件和二进制参与计算；已初始化子模块递归绑定其工作区，未初始化子模块记录该状态和索引提交。mtime 不作为内容。范围规则排序后参与指纹；改变排除规则后不能复用旧记录。

默认未跟踪文件和引用检索排除 `.git`、`node_modules`、`.venv`、`venv`、`__pycache__`、`.cache`、`.next`、`.nuxt`、`dist`、`build`、`target`、`coverage`；可重复 `--exclude-dir NAME` 添加完整目录名。已跟踪内容始终参与指纹，包括被忽略的已跟踪文件。忽略的专用产物不纳入未跟踪范围，不能把业务源文件藏入产物目录来获得验收。

`collect` 必须给出 `--base` 和 `--plan`。Git 计划原件用 `--plan-ref` 指定批准版本；本地原件用 `--plan-origin` 记录用户指定的权威来源。计划包按原文件读取，不重写成需求摘要。哈希验证完整性，不证明本地原件的权威性；来源真实性仍由提供原件的人负责。

重复 `--run PATH/run.json` 复用执行记录。脚本核对记录与流文件哈希、仓库身份、前后指纹一致性及当前指纹；脏记录、过期记录、被中断或无法绑定的记录不能作为通过证据。无执行记录也可收集，但不能据此声称新增逻辑已有测试证明。

## 差异与自动静态检查

差异分别保存基准到 HEAD（committed）、HEAD 到索引（staged）、索引到工作区（unstaged）及范围内未跟踪文件（untracked）。每条清单记录携带 layer，路径可在不同层重复；暂存内容与工作区内容相互抵消时也保留两份原始 diff，不合并成净差异。每层的变更前后 SHA-256 来自该层真实版本，而非统一读取最终工作区。禁止外部 diff/textconv，保留删除和重命名状态；未合并冲突拒绝收集。

默认锁文件名称包括 npm/yarn/pnpm/bun、Cargo、uv/Poetry/Pipenv、Composer、Bundler 和 NuGet 的常用标准锁文件名。`--include-lockfiles` 可显式纳入文本差异。二进制按 Git 分类或 NUL 字节识别。默认省略的锁文件与二进制只进入文件清单，不生成逐行 patch；其哈希仍绑定证据。

删除/重命名文件生成旧路径、模块路径和文件名检索词；源码/配置删除行保守提取符号候选，过滤通用语言关键字，作为导出移除的补充检测。此规则是启发式候选提取，不声称具备完整的各语言语义解析。

引用范围为全仓已跟踪文件及非忽略未跟踪文本，包含隐藏配置、文档和锁文件，并应用记录的目录排除项，不跟随符号链接。锁文件省略逐行 diff，但删除项引用的原始检索命中仍保留。命令以固定字符串方式执行，长文件清单分批执行，完整保存检索词、文件范围、排除项、命令及原始输出。`rg` 退出码 1 表示无命中，其他非零错误不能作为“没有引用”的证据。

执行日志与来源元数据统一归入第三类原始执行证据。未修改调用方和动态契约无法由现有材料证明时，评审者仍应报告缺口，不以静态扫描替代运行契约。

## 冻结与大小

`bundle.json` 保存原字节、逐文件 SHA-256、统一 LF 的引用视图、基准与工作区指纹。评审视图将每个来源展开为 `lines: [{citationId: "C1.1", number: 1, text: "原文"}, ...]`。短行定位符由冻结来源顺序（从 1 开始）和原文行号确定，完整证据 ID 仍绑定内容 SHA-256；来源顺序和原件均由包哈希绑定。空白行保留原文和行号，但不提供可引用的定位符。视图包含全部原文行，不预填覆盖矩阵或结论。评审侧只收到计划、diff/文件清单、执行记录及采集元数据，没有实现者总结入口。

核心证据为实际待发送表示的 UTF-8 字节数，默认上限 2 MiB；`--max-evidence-bytes N` 可显式调整。collect 将 `evidenceEncoding` 与 `coreBytes` 一同冻结并参与包哈希：小包为 `json-lines-v1`；JSON 超过 256 KiB 且行表更小时，使用 `line-table-v1`。超限报告总量、各来源原文大小及上限，不写可评审包，不截断、不用摘要替代。原字节的 Base64 存档不重复计入发送字节。目标模型自身的上下文限制仍可能更小，调用拒绝时报告 ERROR。

行表首行 JSON 保留全部采集元数据，并增加 sourceCount 和列说明；每个来源先有 JSON source 元数据与 lineCount，随后严格对应 lineCount 行。每行以 `citationId<TAB>原文` 表示；无定位符的空白行用十进制行号。只拆第一个 TAB，后续 TAB 和所有原文字符保持原样，行号来自定位符或十进制列。编码后必须可完整还原为原引用视图，不能省略字段或用概述替代。原文含原生客户端可能清除的控制字符时，使用可逆 JSON 转义表示。

没有 evidenceEncoding 的旧包仍按原 JSON 字节数验签。Antigravity 可在发送前将其无损转换为更小的行表；`packet-format.json` 记录旧包哈希、冻结预算、实际表示、发送字节数与完整请求 SHA-256。转义后的表示若超出原包上限则报 ERROR，不能隐式扩大预算。

Antigravity 每次内联消息不超过 144 KiB（含传输信封），按 UTF-8 字符边界分割完整请求，在同一新会话逐段送入。每段尾部使用独立随机确认串，未精确确认则停止；全部加载后才请求原始裁决。`inline-transport.json` 保存顺序、字节数及分段 SHA-256；`transport/` 保存实际逐轮请求、确认与最终请求，`agent-response.raw` 仅为最终回应，避免将确认混入裁决 JSON。`inline-progress.json` 的 done 只表示传输完成。

分段、推理、取消与清理共用总超时，不为每段重置预算。传输时要求原生 ACP 上下文遥测；占用下降、达到容量或缺少遥测均拒绝评审，防止将可能已压缩的历史用于通过验收。`transport-context.json` 保留原始占用数值；检查依赖 Agent 报告，不是对服务端内部处理的字节级证明。不得将分段改成独立评审后汇总，也不接受实现者总结。

收集前后及评审前后重新计算工作区指纹。指纹不同则证据过期，不采纳为当前代码的验收。前后指纹不构成对执行期间全部瞬间状态的连续监测。

## 输出与引用

评审 JSON 的完整结构由 [reviewPrompt / parseVerdict](../scripts/lib/verdict.mjs) 定义：`verdict`、三个 `checks`、逐需求 `items`、`findings` 和 `gaps`。需求覆盖不可为不适用；删除和断言检查可给出有差异证据支持的 `NOT_APPLICABLE`。存在缺陷为 FAIL；无缺陷但有缺口为 INSUFFICIENT_EVIDENCE；其余才可 PASS。assertions 的 PASS 须引用退出码为 0 的实际测试记录。

每个检查、需求、发现和缺口须包含 `citations`。推荐直接选择非空原文行在冻结包内固定的短定位符，字符串和对象写法均可：

```json
"C1.3"
```

同一定位符也可写为 `{"citationId":"C1.3"}`；格式示例不代表实际证据，必须选择该包真实提供的非空行定位符。脚本根据 ID 从冻结原件确定性展开为完整来源、行范围和逐字引文，再执行相同校验。未知 ID、空白行或与同时给出的显式字段冲突，均直接 ERROR；不会搜索相似引文、修正错行、改写评审意见或采纳旧的无效响应。多行证据可逐行引用。自定义适配器也可直接提交完整形式：

```json
{
  "sourceId": "使用证据包中的实际 ID",
  "kind": "plan",
  "startLine": 1,
  "endLine": 1,
  "quote": "所选完整行的逐字原文"
}
```

`kind` 为 `plan`、`diff` 或 `execution`，必须与来源匹配。行号从 1 开始，quote 等于范围内完整行用 LF 连接的字符串，不带行号、不用省略号或空白引文。需求还须引用对应原计划，PASS 需求同时引用实现或执行证据。脚本验证引用存在性及机械一致性，模型判断支持关系和覆盖完整性。

最终 verdict.json 统一包含完整引用字段，并为 ID 形式保留 citationId。Agent 原始响应另存；确定性展开属于引用表示转换，不修复 Agent 提交的任何错误字段。

测试输出可用 TAP reporter 将稳定的测试名称与耗时分开，减少引用数值时的转录错误；这不改变原始输出，也不允许自动修正评审者的错引。

未知 ID、类型错误、越界、引文不符、缺失检查或自相矛盾的响应均为 ERROR，不选择性保留原通过结论。输出为 `verdict.json`、`verdict.md`、`request.txt`、Agent 原始 stdout/stderr 和 `agent-response.raw`；这些产物保持忽略，不进入正式文档或公开提交。

| 状态 | 裁决退出码 |
| --- | --- |
| PASS | 0 |
| FAIL | 1 |
| INSUFFICIENT_EVIDENCE | 2 |
| ERROR | 3 |
